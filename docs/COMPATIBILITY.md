Unverified upstream versions disable the affected controls by design. Keep native identity, focus, generation, request and draft checks even for a verified version. For the fixture-first verification process and exact gate locations, see [CONTRIBUTING.md](../CONTRIBUTING.md#verifying-another-upstream-version). Fixture success and universal compilation do not establish physical-device, clean-Mac or Intel execution support.

Controls need both provider support and backend capabilities. Herdr TUI has no verified composer cursor, so staged Send, Steer and Queue remain unavailable. Claude native controls require 2.1.319 and explicit hook/control opt-ins, and use hooks only. DeckShep never changes a Claude Code or Codex status line; in Rex, Codex Model, Effort, Reviewer, Mode, Interrupt and prompt staging read the session ID from the user's own footer. Rex clipboard checks, Herdr title matching, Claude controls/hooks and experimental Herdr App are off on fresh installs.

Herdr App's source APIs are documented in [ADR 0004](adr/0004-herdr-app-backend.md). No production Herdr App transport or input is enabled. The experimental App profile has request-only routing and separate default-off focus-request consent. Production App build records remain empty, so its controls stay inactive. The packaged peer helper installs no code into Herdr. Existing v2 preferences stay byte-compatible while the flag is off; experimental v3 has an explicit tested v2 rollback projection.
