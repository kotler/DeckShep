# Goldfish review of Herdr App navigation

**Verdict:** Changes requested on `dab404b` before signing off the experimental profile. The highest-priority issues concern which pane receives a focus request and when a cached roster can authorize a local press. No finding demonstrated terminal input, a provider settings write, or an automatic retry.

Three fresh-context Goldfish reviewed the implementation against the [approved design](../../HERDR-APP-NAVIGATION-DESIGN.md) at `f61ff21`. Their scopes were focus and source ownership, acceptance criteria and fixtures, and the visible interface and documentation. The review context included the [version-pinned Herdr Core README](herdr-core-README.md).

## Documentation findings

1. **P2 — The profile guide contradicts its own key map.** It says Herdr App offers Attention, then says it does not. The preview section and generated compatibility guide also imply empty production build records disable local navigation. Describe tap-only Attention, deck-local navigation after a validated read, and the separate build/consent requirement for a focus request. Update the generator along with its output. [Profile guide](../../../PROFILES.md#L82) · [Preview section](../../../PROFILES.md#L102) · [Compatibility generator](../../../../scripts/compatibility.mjs#L9)
2. **P2 — The hardware walkthrough cannot produce the keys it asks the tester to press.** Its launcher creates two plain `/bin/cat` terminals. Step 4 expects two agent tiles and Next. The approved roster excludes these panes, and revoking focus consent leaves local navigation available. Preserve plain terminals for calibration, and distinguish that exercise from a navigation walkthrough using App-reported agents. [Walkthrough](../../../HERDR-APP-HARDWARE-TEST.md#L30) · [Roster](../../../../src/domain/app-navigation.ts#L36)

## Verification and remaining evidence

- The review reran 41 focused tests covering the App view, focus authority, controller and sender contract. All passed. Six additional temporary scenarios exercised the real controller and guarded sender with private sockets. They reproduced both stale destinations, helper loss, Core contention, the selection-marker sequence and preflight expiry. Separate in-memory SVG comparisons verified the mode and classic-style findings.
- Existing contracts exercise raw nullable calibration providers, rejection of missing evidence, one-use permits and uncertain post-write outcomes. Existing controller and browser fixtures cover off-bank Attention and stale targets that have recovered. Those cases differ from a still-eligible target overtaken by another agent.
- **A5/A10/A17.** The suite separately tests listing reorder before key-down and an override change while queued. Add a queued listing reorder. The cost test counts reference reads at two retained-slot sizes. It does not measure map operations across repeated churn and release. Notice-expiry tests count image frames, while warm/cold draw counts and arming-only assertions cover tile closure. [Controller fixtures](../../../../tests/integration/herdr-app-controller.test.js) · [Cost fixture](../../../../tests/unit/herdr-app-view.test.js#L97)
- **A13.** The inspector browser test verifies outgoing settings and preserved scope. Its socket fixture discards `setSettings`. Replay both settings events and check the refreshed inspector value and the controller’s restored position-default action. [Browser fixture](../../../../tests/e2e/inspector.spec.ts#L52)
- **A16 and release evidence.** Git contains one implementation commit. The four per-checkpoint verification runs cannot be established from that history. The existing local package records a dirty `f61ff21` tree in its build metadata. It supports the Rex-only packaging observation but does not establish a reproducible build of `dab404b`. This review did not rerun the full browser suite, build a new package, or exercise live Herdr or physical hardware.
