## Z1 — Major — Investigate recipient feasibility before changing shared production authority

Affected lines 156–168, 197–227 and 258–269.

The ordered plan changes shared press contexts, input actions, delivery and permit checks, then implements synthetic receivers and browser integrations before step 8 investigates the real receiver contract. Both current routes already lack essential capabilities. Production integration could be built around invented receiver revisions, tickets and operation stages that the eventual supported interface cannot supply, or supplies differently. Keeping activation disabled prevents user effects while still allowing speculative architecture and rework.

Deliver passive tracking independently, then move source/interface investigation ahead of shared active-control changes. Require a concrete authoritative App/Core binding and supported recipient contract before committing active evidence fields and orchestration to production modules. Keep early contract experiments in test-owned helpers using the existing native picker and daemon code. Continue evaluating both candidates and defer full delivery/browser integration until actual contracts are known.

Evidence includes target lines 156, 162 and 202, the [evaluation](../../herdr-app-agent-controls/delivery_evaluation.md) at line 8, and the existing entry points in `src/agents/codex/keyboard-settings.ts` at line 372, `src/agents/codex/daemon.ts` at line 808 and `src/app/delivery.ts` at line 255.
