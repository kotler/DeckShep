# Bringing the Herdr App Codex Model key into production

Owner sequencing update, 2026-11-15: prepare Herdr App navigation for 1.5.0 first.
Agent controls remain deferred. The released third row is blank; the prototype
and target cue described below are future controls work. See
[ADR 0008](../adr/0008-herdr-app-navigation-release.md).

The first deliverable is an opt-in Model key in a private DeckShep build. A user selects a ready Codex pane in Herdr, switches back to their editor, and presses Model on the Stream Deck. One press selects the next entry in that chat’s native picker, including wraparound, preserves reasoning effort and saved defaults, and leaves the editor focused. Browsing another bank on the deck preserves the compact target cue. Additional Codex and Claude controls can follow once they have their own evidence. Public distribution is a separate owner decision.

The active implementation goal covers every control Rex supports for Codex and Claude Code, using a Herdr App mod. Model is the first shared delivery checkpoint. Completion also requires the following provider/state coverage through ordinary Stream Deck host events, foreground and background native tests, and installation of the qualified mod/helper path.

## 1. Decide whether the mod can deliver safely on stock Herdr

Start in the existing isolated harness. Run the first two investigations independently. A positive result needs both an observable native test and an explanation of which supported interface enforces the condition. Repeated passes through a timing window cannot establish that guarantee.

| Investigation | Experiment and decision |
| --- | --- |
| Can accepted input arrive late? | Use a test-owned terminal that records bytes it actually receives. Exercise Core’s busy input gate with another owned operation. Establish that the gate is holding an ordinary attach DATA frame, then revoke the press before its deadline and release the gate. Repeat with expiry alone, a closed viewer, and a later step after an earlier effect. Drain the queue and count bytes at the terminal. Include a positive control that releases valid input. If held bytes arrive late, disqualify that transport unless a supported mechanism orders retirement and expiry at delivery. If acceptance or drain cannot be observed, mark the result unresolved. |
| Which running chat owns the selected pane? | Start two offline CLIs in the same folder and two Cores with overlapping terminal addresses. Start discovery after the sessions already exist. Keep launcher facts on the assertion side of the test. Map each production observation to the App process and window, its actual Core connection and lifetime, the pane and terminal lifetime, and the CLI process and root chat. Exercise pane closure, CLI replacement, chat resume, reconnect, and a switch away and back between mod renders. Require old presses to expire on every break in continuity, including a ready → working → ready transition. Titles, folders and identical screenshots can be identical across sessions. |
| Does an active viewer coexist with Herdr? | Resize the App while attached, during a picker cycle, and after helper disconnect. Record the App’s dimensions, Core’s active viewer, cursor and final terminal size. Exercise ordinary user typing as well. Require correct App sizing, intact user input and cancellation of any step whose expected screen or cursor changed. |
| Can DeckShep verify the result without typing again? | Find a supported, independent observation of the target session’s current model and effort, including when the composer footer is hidden. Check the approved one-second postflight budget and proof of no pending writes. The prototype’s second picker operation is a test oracle. Production settlement and inspector Refresh must be observation-only. |

Record the interface, revisions, counterexamples and result for each row in the [delivery evaluation](herdr-app-agent-controls/delivery_evaluation.md). The native mod is the first candidate because it already exercises Rex’s picker algorithm. Keep the provider settings API as an independently evaluated candidate. It must prove the same binding, conditional application, background behavior, draft eligibility, picker order and session-only result. Existing API probes found different ordering and effort-based skipping. Select a single qualified route before issuing any press. If both qualify, present the measured trade-offs for the owner’s choice. If neither qualifies using existing interfaces, retain the informational key and document the failed condition. Upstream changes and weaker guards are outside this plan.

## 2. Extract the qualified route into DeckShep

Use the route decision to identify the exact runtime APIs, files and compatibility evidence before enabling writes. For the mod path, extract the non-focusable mod and fixed relay from [the native harness](../../tests/live/herdr-app-model/) and the stream decoder from [the test helper](../../tests/helpers/herdr-app-mod-stream.ts). Keep process launching, synthetic capabilities, hold points and picker inspection in tests. Build the relay for supported Mac architectures and bundle and audit the runtime decoder dependency if the selected route needs it.

Use a user-level helper supervised by the experimental DeckShep plugin as the proposed lifecycle. Start it on demand for the configured Herdr installation. Use a private, owner-only socket, verified peers and a versioned, size-bounded protocol for Model. Bind each request to its operation, target, exact payload and one-use step. On disconnect, sleep, restart or protocol mismatch, retire outstanding authority. A replacement helper must prove the previous operation closed before it can rearm the same target. Test duplicate starts and a crash on either side of the final write. Keep terminal content, prompts, paths and credentials out of diagnostics.

Compose Herdr observations and Codex evidence in the [App controller](../../src/app/herdr-app-controller.ts). Keep terminal transport in the Herdr backend and picker semantics in the [shared Codex implementation](../../src/agents/codex/keyboard-settings.ts). Route every mutation through the [delivery kernel](../../src/app/delivery.ts) with a real Model-specific verification record. A successful helper handshake alone grants no input capability.

Capture the presented target at key-down on the ordinary host path. Preserve the 350 ms arming delay and one monotonic two-second deadline across all stages. Verify clock agreement and enforce the deadline where each effect happens. Retire on consent loss, focus or state change, remapping, disappearance or source replacement. Ignore duplicate presses while pending. Publish the model only after independent same-session readback. For partial or uncertain delivery, show `Check Codex`, quarantine the affected target across reconnects and require explicit observation-only Refresh with no pending effects before rearming. A late reply can complete only its original operation. The approved design specifies the exact outcomes and recovery rules.

## 3. Make installation reversible

Expose **Install Herdr controls** in experimental App setup. Resolve the configured Herdr App home and show the affected layout before applying changes. Install the bundled mod under its own directory in that home’s `mods/`, with `main.js` and a non-focusable `mod.json`. Supply the packaged helper and relay from a DeckShep-owned location. Stage files, verify their manifest, then activate them. Give the user a separate Model input opt-in after setup demonstrates a healthy connection.

The prototype creates an entire disposable layout. For everyday Herdr, preserve the user’s layout and other mods. Prefer an additive non-focusable block in a managed copy of the selected layout, with the original selection recorded. Detect layout changes between preview and apply. Verify that Herdr loaded the expected mod after a supported reload or the user’s next normal start. Report installed, loaded, connected and eligible separately in the inspector so a missing layout block is diagnosable. On Herdr restart, reconnect through the verified endpoint without asking the user to change socket permissions.

Track managed files and layout edits in an installation receipt. Exercise fresh install, repeat install, interrupted upgrade, custom App home, layout edited after install, and uninstall. Disable must retire input immediately. Uninstall must stop the owned helper and remove only managed content. Restore the previous layout selection when it still applies, and preserve user edits if it has diverged. An incompatible update should leave navigation available and report Model’s compatibility state.

**First implementation result, November 14, 2026.** The [Core-held input test](../../tests/live/playwright/input-gate.spec.js) reproduced late input at the actual disposable recipient. One byte arrived 3926 ms after the press even though its writer requested closure at 13 ms. An ordinary queued terminal.keys call also delivered at 3937 ms after its client closed at 7 ms. The positive control and expiry/partial cases completed, with owned cleanup and unchanged tracked settings. Both native transports fail the required deadline and retirement behavior. [Native evidence](../validation/2026-11-14-herdr-core-input-gate.md)

The next delivery task must find a supported route that prevents accepted work from taking effect after retirement or expiry. A local helper check or socket close cannot supply that behavior for the tested Core gate. Carry the existing provider API candidate forward with its binding and Rex-equivalence requirements. Use the [native test runbook](../../tests/e2e/README.md) and its current authorization requirements for live runs.
